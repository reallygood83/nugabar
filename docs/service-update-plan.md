# 누가바 서비스 업데이트 계획

## 기획의도

누가바는 단순한 AI 문장 생성기가 아니라 교사가 생활기록부 작성 과정에서 반복적으로 수행하는 관찰 정리, 행동특성 작성, 누가기록 작성, NEIS 입력 준비를 하나의 안전한 업무 흐름으로 줄이는 서비스다.

핵심 가치는 다음 네 가지다.

- 교사의 기록 작성 시간을 크게 줄인다.
- 행동특성 및 누가기록 문장의 품질을 NEIS 제출 가능한 수준으로 유지한다.
- 학생 데이터와 교사별 Gemini API 키를 서버에 불필요하게 저장하지 않는다.
- 학급, 학생, 기록을 교사 업무 순서에 맞게 이어준다.

## 현재 진단

- 기능은 행동특성, 누가기록, 창체 누가기록, 학급 관리로 나뉘어 있으나 교사의 실제 흐름은 아직 한 화면에서 자연스럽게 이어지지 않는다.
- Gemini 모델은 2.5 Flash로 고정되어 있고 API 키는 브라우저 로컬 저장 방식으로 정리되었지만, 설정/인증/저장 실패에 대한 사용자 안내는 더 다듬어야 한다.
- 행동특성 생성 품질은 최소 분량과 종결어미 검증이 강화되었으나, 업데이트마다 품질이 유지되는지 확인하는 회귀 테스트가 필요하다.
- 생성 중 외부 구독 모달은 교사의 핵심 작업을 방해하므로 기록 생성 흐름에서 제거한다.
- 자동화된 E2E QA와 AI 결과물 golden test가 아직 부족하다.

## 업데이트 원칙

1. 업무 흐름 우선: 기능 추가보다 학급 생성부터 NEIS 복사/엑셀 출력까지의 흐름을 먼저 안정화한다.
2. 품질 게이트 우선: AI 결과는 생성 성공만으로 통과시키지 않고 분량, 문체, 금지 표현, 종결어미를 검증한다.
3. 개인정보 최소화: Gemini API 키는 서버에 저장하지 않고, 민감한 학생 정보는 필요한 범위에서만 다룬다.
4. 작은 배포 단위: Vercel 자동 배포에 맞춰 작은 커밋으로 변경하고 매번 타입체크와 린트를 통과시킨다.

## 단계별 실행 계획

### 0단계: 안정화

- Vercel 배포 설정, Firebase Admin 환경변수, 로그인 후 API 401 여부를 확인한다.
- Gemini 2.5 Flash 고정 상태를 유지한다.
- API 키 서버 저장 경로가 실제 저장을 하지 않는지 유지한다.
- 생성 중 구독 모달을 제거해 핵심 업무 흐름을 끊지 않게 한다.

완료 기준:

- 로그인 후 행동특성, 누가기록, 학급 API가 인증 토큰으로 호출된다.
- 행동특성 생성 중 구독 모달이 뜨지 않는다.
- 타입체크와 린트가 통과한다.

### 1단계: 교사 업무 대시보드

- 첫 화면을 기능 소개보다 "학급 선택", "최근 작업", "바로 생성", "저장된 기록" 중심으로 재구성한다.
- alert 기반 성공/실패 메시지를 화면 안의 상태 메시지로 바꾼다.
- 학급/학생이 없을 때 다음 행동을 안내하는 빈 상태를 추가한다.

완료 기준:

- 신규 사용자가 로그인 후 학급 생성, 학생 추가, 행동특성 생성까지 막힘 없이 진행한다.
- 저장 실패와 인증 실패가 alert가 아닌 복구 가능한 화면 메시지로 표시된다.

### 2단계: AI 품질 회귀 테스트

- 행동특성 golden case를 20개 이상 만든다.
- 누가기록 golden case를 20개 이상 만든다.
- 각 case는 키워드, 기대 분량, 금지 표현, 종결어미, 최소 품질 설명을 가진다.
- 생성 결과가 기준 미달이면 API가 재시도하거나 명확히 실패한다.

완료 기준:

- golden case 90% 이상이 기준을 통과한다.
- "돕는함", "대하는함", "했습니다" 같은 실패 패턴이 자동으로 잡힌다.

### 3단계: 기록 워크스페이스

- 학생 상세 화면에 행동특성, 누가기록, 창체 기록을 시간순으로 모은다.
- 생성 결과의 수정, 복사, CSV/Excel 출력 상태를 명확히 보여준다.
- 행동특성에서 누가기록으로 넘어가는 임시 저장 흐름을 더 안전하게 만든다.

완료 기준:

- 학생 한 명 기준으로 행동특성 생성, 누가기록 생성, 저장, 상세 확인, 복사/출력이 한 흐름으로 완료된다.

### 4단계: 보안/운영 QA

- Firestore rules와 서버 API 권한 검증의 역할을 분리해 문서화한다.
- 배포 후 핵심 URL과 API의 smoke test를 자동화한다.
- 민감정보가 콘솔 로그나 응답에 노출되지 않는지 확인한다.

완료 기준:

- 다른 사용자 데이터 접근이 차단된다.
- 서버 로그에 API 키와 학생 실명이 불필요하게 남지 않는다.
- 배포 후 smoke test 결과를 확인할 수 있다.

## QA 체크리스트

- 인증: 로그인 전 API 차단, 로그인 후 핵심 API 성공, 토큰 만료 시 안내.
- 생성: 행동특성 350자 이상, 누가기록 100~150자 권장, Gemini 2.5 Flash 사용.
- 저장: 학급, 학생, 행동특성 임시 저장, 누가기록 Firestore 저장.
- UX: 생성 중 방해 모달 없음, 실패 메시지 명확, 복사/다운로드 작동.
- 보안: API 키 서버 저장 없음, 사용자별 데이터 격리, 민감정보 로그 최소화.
- 배포: Vercel build 성공, Production alias 정상, 배포 직후 오류 로그 확인.

## 다음 작업 순서

1. 0단계 안정화 변경을 배포한다.
2. 배포된 서비스에서 로그인 후 행동특성 생성과 누가기록 저장을 smoke test한다.
3. alert 제거와 인앱 상태 메시지 전환을 작업한다.
4. AI golden case 기반 회귀 테스트를 추가한다.
